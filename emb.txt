CURRENT CHUNKING CONTRACT:
- Chunking returns list[ChunkGroup].
- Each ChunkGroup contains:
    parent: Document
    children: list[Document]
- Parent/child metadata already includes document_id, document_checksum,
  parent_id, child_id, parent_index, child_index, parent_checksum,

- Do NOT redesign their generation.

- Dimension: 384
- Local inference only; no OpenAI/Groq/API embedding service.
- Parent and Child chunks will both be embedded in a later sub-phase.
- The model must be loaded once and reused; never reload it for every chunk.
- Embedding must ADD vectors without destroying or rebuilding existing metadata.

    embed_chunks(...)

The orchestrator must call this public function rather than directly
calling model.encode() or any internal model implementation.

Keep the public interface clean and suitable for Sub-phase 2, where actual
Parent + Child ChunkGroup embedding will be implemented.

- document_id is the stable logical-document identity.
- document_checksum identifies source-document content.
- chunking_config_hash identifies the chunking configuration.
- parent_id/child_id must NOT be used as the deterministic Qdrant storage

You are acting as a Senior AI Engineer working on a production-oriented RAG ingestion pipeline.

ARCHITECTURE IS LOCKED:

Loading
  ↓

  ↓
Chunking
  ↓
create_parent_child_chunks(...)
  ↓

  ↓

  ↓

  ↓

Do NOT redesign this architecture.

CURRENT EMBEDDING DECISIONS:
- Model: BAAI/bge-small-en-v1.5
- Dimension: 384
- Local inference only
- normalize_embeddings=True
- BGEEmbeddingModel already exists from Sub-phase 1.
- Public Embedding entry point is embed_chunks(...).
- Parent and Child chunks must both be embedded.
- Qdrant/Storage is a future phase.

INPUT:
embed_chunks(...) receives the existing:
    list[ChunkGroup]

Each ChunkGroup contains:
    parent: Document
    children: list[Document]

REQUIREMENTS:

1. Generate a 384-dimensional embedding from ONLY:
       Document.page_content

   Do NOT embed metadata.

2. Generate one embedding for every Parent.

3. Generate one embedding for every Child.

4. Preserve the complete existing metadata of every Document.
   Do not delete, rename, overwrite, fabricate, or reconstruct metadata.

   Important metadata includes, where already present:
   - document_id
   - document_checksum
   - source_file
   - source_path
   - domain
   - document_type
   - loader_used
   - page_number
   - character_count
   - is_empty_page
   - ingested_at
   - parent_id
   - parent_index
   - parent_checksum
   - child_id
   - child_index
   - child_checksum
   - chunking_config_hash
   - page_start
   - page_end
   - status
   - version
   - updated_at
   - indexed_at

   Do not add new filtering logic in this phase.
   These metadata fields will later be stored as Qdrant payload by Storage.

5. Preserve the Parent → Child relationship exactly.
   child.parent_id must continue to identify its parent.

6. The resulting embedding output must make both:
       Document + embedding
   available to the later Storage phase.

   Do not put the embedding inside Document.metadata unless that is
   already the established project design. Keep vector data separate
   from metadata so Storage can later create:
       Qdrant point = point_id + vector + payload(metadata)

7. Reuse the supplied BGEEmbeddingModel when one is passed to
   embed_chunks(...).
   Do not create/load another model for every chunk.

8. Do not modify:
   - Loading
   - Chunking
   - ChunkGroup
   - parent_id/child_id generation
   - document checksums
   - parent/child checksums
   - chunking_config_hash
   - chunk sizes/overlaps
   - existing lifecycle fields
   - existing logging architecture

9. Do NOT implement:
   - Qdrant
   - Storage
   - Retrieval
   - metadata filtering
   - Groq/LLM calls
   - deterministic Qdrant Point IDs
   - ACTIVE/INACTIVE generation transitions

   Those belong to later phases.

FAULT ISOLATION:
10. Treat each Parent + all of its Children as one embedding group.

11. If the Parent or any Child in a group fails to embed:
    - do not return an incomplete group;
    - log the failure without logging page content or vector values;
    - continue processing independent groups;
    - do not silently swallow unexpected errors.

12. Successful independent groups must still be returned.

OUTPUT CONTRACT:
13. Keep the public function:
       embed_chunks(...)

14. Return a structure that preserves the existing Parent/Child hierarchy
    and provides the generated embeddings separately from metadata.

15. Do not change the existing ChunkGroup contract unless absolutely
    necessary. If an embedding result structure is required, introduce
    the smallest clean structure needed for the later Storage phase.

- Parent metadata is preserved exactly.
- Child metadata is preserved exactly.
- parent_id relationship is preserved.

- document_checksum is preserved.
- parent_checksum/child_checksum are preserved.
- chunking_config_hash is preserved.
- Multiple children are handled correctly.
- A failed child does not produce an incomplete group.
- A failed group does not stop another independent group.
- The supplied BGEEmbeddingModel is reused.
- No metadata is passed as embedding input.

QUALITY CONSTRAINTS:

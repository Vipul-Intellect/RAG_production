==================================================
VERY IMPORTANT: HASH SEMANTICS
==================================================

document_checksum represents the source document content.

chunking_config_hash represents the actual chunking configuration.

Our existing chunking_config_hash is calculated from:

    splitter
    parent_chunk_size
    parent_chunk_overlap
    child_chunk_size
    child_chunk_overlap

Therefore:

1. If document content changes:
       document_checksum changes
       chunking_config_hash stays the same
       → NEW generation

2. If chunking configuration changes:
       document_checksum stays the same
       chunking_config_hash changes
       → NEW generation

3. If both change:
       both values change
       → NEW generation

4. If neither changes:
       same generation

Do NOT increment chunking_config_hash manually.
It is a deterministic SHA-256 configuration fingerprint.
